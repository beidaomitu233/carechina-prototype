# 外籍来华旅游就医平台：首页重构研究与信息架构

> 版本：v1.0 · 2026-08-31  
> 研究范围：现有 `dashboard.html`、`仪表盘设计说明.md`、`沙特出境就医分析.xlsx`，以及医疗旅游、国际患者服务、医院、企业与政务服务网站。

## 1. 结论先行

当前稿的视觉完成度不低，但产品形态错位：它把首页做成了包含 8 个选项卡的大型功能演示，用户必须逐个切换才能理解平台。真正的官网首页应是一条连续的患者决策链：

1. 我这种病是否可以来中国治疗？
2. 平台和医院是否可信？
3. 谁会负责我的病例，如何匹配医院？
4. 出发前能知道哪些信息，费用边界是否清楚？
5. 签证、语言、接送、陪同、支付和回国随访由谁协调？
6. 我现在应该提交什么资料，多久会得到回复？

因此，新首页采用“官网 + 服务入口”而不是“仪表盘”结构。首页负责说服和分流；医院库、治疗方案、费用估算、病例提交等是独立工具或后续页面。

## 2. 对业务的理解

### 2.1 产品不是单纯的医院目录

平台提供的是跨境医疗协调服务，核心价值不是展示医院数量，而是把患者、医疗协调员、中国医院、翻译、签证与行程服务组织成一个可执行的治疗旅程。

平台至少存在三类服务关系：

| 关系 | 用户真正购买的价值 | 首页需要证明什么 |
|---|---|---|
| 患者/家属 → 平台 | 降低选择风险和协调成本 | 有人负责、流程透明、资料安全、医院匹配有依据 |
| 平台 → 医院 | 提供合格病例、跨境沟通与院外协调 | 病历标准化、患者预期管理、付款与行程可协调 |
| 政府/使领馆/保险/转诊机构 → 平台 | 可追踪的转诊与支付协同 | 合规、责任边界、文件完整、可提供对公联络 |

### 2.2 工作簿能支撑什么

附件的有效业务信息主要集中在：

- 沙特出境就医的高需求病种：肿瘤、复杂心血管、神经外科、器官移植、血液病、复杂骨科、生殖医学、眼科、儿科复杂病例、整形重建、口腔种植等。
- 武汉、成都、广州三座城市的医疗资源、航线和穆斯林服务差异。
- 17 家医院的优势专科、特色技术和国际患者服务描述。
- 沙特政府出境就医的审批、付款与陪同人员场景，说明产品不能只服务自费散客，还需要支持政府/机构支付者。

这些资料适合作为“目标市场假设和内容线索”，不应直接变成未经复核的公开营销事实。

### 2.3 当前公开数据的证据边界

现有页面出现了“103 家合作医院、22 城、92 国、平均 2.1 天入院、节省 60%、CAR-T 缓解率 90%”等强主张，但工作簿原始表只明确列出 17 家医院和 3 个重点城市。其他数字来自设计稿后续补充、示意模型或二次整理，并非同一份可审计的数据源。

重构原则：

- 不能把“榜单收录医院”写成“合作医院”。
- 不能把示意等待时间、价格模型或病例故事当作真实服务结果。
- 医院排名需标注年份、榜单名称和专科/综合口径。
- 文化配套、保险直付、清真餐、祈祷室、语言支持需要由医院逐项确认。
- 病例故事必须取得授权并脱敏；没有真实病例时使用“服务场景”，不伪造患者评价。

## 3. 当前页面诊断

### 3.1 产品结构问题

| 问题 | 对用户的影响 | 重构方式 |
|---|---|---|
| 8 个导航选项卡互相隔离 | 患者无法通过自然滚动形成完整理解 | 首页改为连续叙事；工具进入独立页面 |
| “Why China”成为默认首页标题 | 先推销目的地，没有先回应病情焦虑 | 首屏改为“提交病例，获得医院与治疗路径建议” |
| 导航同时承担产品功能和内容栏目 | 顶部过载，1280px 已出现换行 | 一级导航收敛为 5 项，突出一个主 CTA |
| 103 家医院一次性进入匹配工具 | 信息量大但缺少匹配依据与可解释性 | 首页只展示重点医疗网络与筛选逻辑；完整医院库单独承载 |
| 费用计算器给出精确结果 | 容易制造错误预期 | 首页只说明费用组成和报价流程；正式报价由医院评估后提供 |
| TCM 自动给出药材克数与煎服方法 | 存在明显医疗安全与合规风险 | 从首页和自动工具移除；仅保留经医生审核的健康教育内容 |
| “先旅游，顺路看病”作为主叙事 | 对肿瘤、移植、重症患者显得轻率 | 改为“治疗优先，康复稳定后可协助安排在华停留” |

### 3.2 UI 问题

- 页面没有任何真实位图，全部依赖 SVG 插画，医疗可信度不足。
- 英文品牌名和 Hero 标题过长，首屏阅读负担大，导航也出现拥挤。
- 深绿、鎏金和伊斯兰纹样被全站高强度使用，容易把“面向所有国际患者”收窄为中东奢华风。
- 大量卡片、徽章、数字和动画同时竞争注意力，主行动入口不够集中。
- 视觉虽然统一，却缺少真实医护人员、医院环境、病例沟通与城市抵达场景。

## 4. 参考网站拆解

### 4.1 医疗旅游与国际患者网站

| 参考 | 可借鉴 | 不直接照搬 |
|---|---|---|
| [Medera Global Health](https://www.medicaltravelchina.org/zh-hans/) | 全幅真实中国场景、首屏单一咨询入口、医疗与目的地结合 | 首图过度偏旅游，医疗证据与服务流程应更靠前 |
| [To China Care](https://www.tochinacare.com/zh-CN/) | 直接说明一站式服务、3 步旅程、高频 FAQ、持续 CTA | 首页内容重复，医院与案例数量过多；部分强数据和故事需核验 |
| [Johns Hopkins International Patients](https://www.hopkinsmedicine.org/international/patients/) | 真实医生与设备照片、单一预约 CTA、专属协调员贯穿全程 | 大型医院品牌已有全球认知，平台不能照搬其权威语气 |
| [Mount Sinai International Patient Services](https://www.mountsinai.org/care/international) | 24/7 单一联系人、费用估算、预约入院、使领馆/机构付款说明 | 页面视觉偏旧，但信息责任边界非常清楚 |
| [HSS International Patient Services](https://www.hss.edu/patient-care/patients-visitors/international) | 用一个强专科和排名建立信任，明确治疗前中后支持 | 本平台为多医院网络，不能只用单一榜单代替匹配逻辑 |
| [TipWay](https://www.tipway.net/) | 强调“真人协调员 + 认证医院 + 文件安全”，正面回应跨境医疗焦虑 | 认证标准必须真实存在，不可泛化使用“verified” |

共同规律：成熟国际患者服务页不会把复杂工具全塞进首屏，而是优先呈现真人协调、治疗前评估、费用和行程透明、语言服务与清晰联系入口。

### 4.2 医院网站

| 参考 | 可借鉴 | 不直接照搬 |
|---|---|---|
| [武汉协和医院](https://www.whuh.com/public.htm) | 大型真实主视觉、百年品牌资产、机构权威感 | 新闻与院内栏目很多，不适合国际患者的跨境决策路径 |
| [武汉市第三医院](https://www.whsyy.net/) | 医院建筑 + 城市地标形成真实地域感，导航克制 | 首屏偏形象宣传，缺少国际患者专属行动入口 |
| [武汉同济医院](https://www.tjh.com.cn/) | 首屏直接分流公众版、国际版、员工/学生版 | 平台无需复制院内多角色入口，但应保留患者/合作机构双入口 |

医院官网的价值主要是提供权威内容和真实素材：建筑、医生、科室、设备、国际医疗部和官方联系方式。平台需要重新组织这些资料，不应复刻医院新闻门户。

### 4.3 企业与政务网站

| 参考 | 可借鉴 | 应用到本项目 |
|---|---|---|
| [徐工官网](https://www.xcmg.com/) | 大面积真实业务图片、导航短、产品入口清楚、固定询价入口 | 用真实医疗场景替代插画；固定“提交病例”入口 |
| [华为官网](https://www.huawei.com/cn/) | 大留白、一个屏幕一个主题、图像承担主要表达、卡片数量克制 | 首屏只传达一个核心承诺；减少徽章和装饰性卡片 |
| [上海一网通办](https://zwdt.sh.gov.cn/) | 以用户任务为核心的大搜索/办理入口，右侧保留“我要办、我要查”等快捷操作 | 首页加入“我需要治疗方案 / 第二意见 / 医院匹配”任务入口 |

可复用的不是色彩和装饰，而是信息原则：一个屏幕解决一个问题；重要任务永远可见；复杂内容用搜索、分类和分层页面承载。

## 5. 推荐网站结构

### 5.1 一级导航

1. 找到合适的医疗（Find Care）
2. 医院与专科（Hospitals & Specialties）
3. 就医流程（How It Works）
4. 患者支持（Patient Support）
5. 关于平台（About）

右侧固定：语言切换 + “提交病例 / Get a Care Plan”。

### 5.2 首页模块顺序

| 顺序 | 模块 | 要回答的问题 | 主要内容 |
|---|---|---|---|
| 1 | Hero + 病例入口 | 你们能帮我什么？下一步是什么？ | 服务承诺、真人协调、主 CTA、真实医患图片 |
| 2 | 信任条 | 这是可靠的医疗服务吗？ | 医院按专科匹配、双语协调、资料隐私、治疗前评估 |
| 3 | 按需求开始 | 我应该从哪里开始？ | 治疗方案、第二意见、医院匹配 3 个任务入口 |
| 4 | 重点专科 | 是否覆盖我的病情？ | 6–8 个高需求专科 + “查看全部” |
| 5 | 匹配逻辑 | 为什么推荐这家医院？ | 病情、专科实力、医生经验、可接收性、预算与文化需求 |
| 6 | 重点医院网络 | 中国有哪些可选资源？ | 武汉/成都/广州医疗网络、代表医院、官方资料来源 |
| 7 | 就医旅程 | 过程会不会失控？ | 提交资料 → 医疗评估 → 确认方案 → 抵达治疗 → 回国随访 |
| 8 | 全程支持 | 谁处理院外问题？ | 签证、翻译、接送、住宿、支付协调、陪同与随访 |
| 9 | 费用边界 | 要花多少钱？ | 费用组成、影响因素、正式报价触发条件，不给虚假即时总价 |
| 10 | FAQ | 还有哪些风险？ | 病历、签证、语言、付款、陪同、隐私、紧急情况 |
| 11 | 轻量病例表单 | 我现在提交什么？ | 先收国家、病情、联系方式；上传病历放到第二步安全流程 |
| 12 | 合作机构入口 + 页脚 | 机构如何转诊？ | 医院、保险、使领馆、政府项目、转诊伙伴独立入口 |

## 6. 三个视角的设计决策

### 6.1 产品视角

- 首页只做理解、信任、分流和转化，不承担完整医院库与报价模型。
- 第一次转化只要求少量信息；医疗资料上传进入明确隐私说明的第二步。
- 医院推荐必须展示“推荐依据”，不能只用综合排名。
- 未来可按国家提供落地页，例如沙特版重点解释政府审批、陪同与清真服务；全球首页保持中性。
- 患者入口与机构转诊入口分开，避免一个表单同时服务 B2C 和 B2G。

### 6.2 UI 视角

- 参考国际医院的真实医患图、企业官网的大图与留白、政务网站的任务入口。
- 主色保留医疗绿色，但从大面积深绿改为白色、浅暖灰和低饱和青绿，金色只做极少量强调。
- 标题使用清晰的无衬线或克制衬线，英文品牌名不占据 Hero 主标题。
- 每屏只保留一个视觉中心；卡片总量减少，取消跑马灯和高频数字动画。
- 图片优先级：真实医患沟通 > 医院空间与设备 > 城市抵达与陪同 > 纯旅游风景。

### 6.3 患者视角

- 语气从“宣传中国”改为“理解你的病情和不确定性”。
- 对重症患者先谈医疗安全和信息透明，再谈旅行便利。
- 明确平台不是医院，不进行诊断；最终治疗方案与报价由接收医院出具。
- 不使用未经证实的“最快、最好、全国第一、保证入院、保证成功”等表达。
- 紧急医疗情况必须提示联系当地急救服务，平台仅处理计划性跨境医疗。

## 7. 图片策略

原型阶段只使用真实摄影，不再使用 AI 医院插画作为主要视觉。建议素材来源分三类：

1. 合作医院正式提供：医生团队、国际医疗部、病房、设备、医院外观；上线首选。
2. 有明确许可的图库：用于“协调员沟通、翻译陪诊、出行准备”等通用场景。
3. 医院官网公开图片：仅用于内部原型参考；正式上线前必须取得使用授权。

每张图片应维护来源、授权范围、人物肖像授权、医院/设备对应关系和适用语言版本。禁止使用与医院名称不对应的“示意建筑图”冒充真实医院。

## 8. 立即移除或暂停上线的内容

- 自动生成中药处方、药材剂量、煎服方法和穴位治疗方案。
- 未经授权的患者姓名、国籍、年龄、疗效与长篇康复故事。
- “咨询到入院 2.1 天”“节省 60%”等无统一数据口径的结果承诺。
- 把榜单医院数量写成合作医院数量。
- 未经医院确认的清真厨房、祈祷室、阿拉伯语、保险直付等服务。
- 把旅游置于治疗之前的“先旅游，顺路看病”主文案。

## 9. 本轮原型落地边界

本轮新建 `home-redesign.html`，保留原 `dashboard.html` 作为历史版本。新版验证以下方向：

- 连续滚动首页而非选项卡首页。
- 真实摄影主视觉。
- 患者任务入口和单一病例提交 CTA。
- 三城医疗网络与重点专科的清晰呈现。
- 治疗流程、服务支持、费用边界与 FAQ。
- 英文默认、中英切换、桌面和移动端响应式。

完整医院检索、病例安全上传、后台表单、阿拉伯语 RTL、真实报价和医院数据同步不在本轮静态原型范围内。
